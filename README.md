# ISIC Košice — канал + бот + каталог для студентов

Telegram-канал с актуальными предложениями для держателей ISIC в Košice, мини-приложение-каталог с поиском и фильтрами, автоматическая проверка и чистка устаревшего, встроенная реклама. **Всё работает на бесплатных облачных сервисах, без своего сервера и без установки чего-либо на компьютер.**

## Как это устроено

```
offers/*.yml  ──►  GitHub Actions (по расписанию)  ──►  Telegram-канал (посты, закреп-меню, подборка недели)
ads/*.yml     ──►   • проверка файлов и ссылок      ──►  GitHub Pages: docs/index.html  (Mini App «Каталог»)
issue-форма   ──►   • архив истёкших и мёртвых      
                    • пометка «Закончилось» в старых постах
```

| Что | Где живёт | Цена |
|---|---|---|
| Хранилище офферов (текстовые файлы) | GitHub-репозиторий (публичный) | 0 |
| Планировщик и скрипты | GitHub Actions | 0 для публичного репо |
| Каталог (Mini App) | GitHub Pages (HTTPS) | 0 |
| Канал и бот | Telegram | 0 |

Бот не отвечает на команды (для этого нужен постоянно работающий сервер). Навигация построена иначе: **закреплённое меню с кнопками категорий**, хэштеги в каждом посте (`#music`, `#events`, …) и Mini App с поиском. Кнопки открывают каталог сразу на нужной категории или конкретном оффере.

## Запуск за ~20 минут

**1. Репозиторий.** На github.com создай *публичный* репозиторий `isic-kosice`, распакуй архив и загрузи всё содержимое (Add file → Upload files; перетащи папки целиком). Проверь, что в репозитории появилась папка `.github/workflows` с 5 файлами. Для Pages и бесплатных минут Actions репозиторий должен быть публичным.

**2. Бот и канал.**
- В Telegram у [@BotFather](https://t.me/BotFather): `/newbot` → получишь токен.
- Создай канал, добавь бота администратором с правами: публиковать, редактировать и закреплять сообщения.

**3. Секреты и настройки репозитория** (Settings):
- *Secrets and variables → Actions → Secrets*: `TELEGRAM_BOT_TOKEN` = токен бота.
- *Actions → General → Workflow permissions*: **Read and write permissions**.
- *Pages → Source*: **GitHub Actions**.
- *Variables*: `INCLUDE_EXAMPLES` = `true` — только пока смотришь демо с тестовыми карточками, потом удали переменную.
- *Issues → Labels*: создай метки `approved`, `submission`, `broken`.

**4. `config.yml`** (правится прямо в браузере): `repo`, `pages_url` (`https://ЛОГИН.github.io/isic-kosice/`), `bot_username`, `channel_id`, `primary_lang` — язык, который виден в посте сразу (остальные сворачиваются под спойлер).

**5. Первый запуск.** Actions → **Maintain catalog** → Run workflow. Через минуту каталог открывается по адресу Pages.

**6. Mini App в Telegram.** У BotFather: `/newapp` → выбери бота → укажи URL каталога (Pages) → короткое имя, например `catalog`. Впиши его в `config.yml` как `app_short_name`. После этого кнопки «📲 Каталог» в канале открывают приложение внутри Telegram.

**7. Меню и первые посты.** Actions → **Post to Telegram** → Run workflow: `command = menu`, `dry_run = true` (посмотреть в логе), затем `false` — меню опубликуется и закрепится. Дальше посты идут сами по расписанию (`post.yml`, по умолчанию утро и вечер, в воскресенье — подборка недели).

**8. Свои офферы.** Удали `example-*.yml` и `INCLUDE_EXAMPLES`, добавь реальные (ниже).

## Как добавить оффер

**Вручную:** скопируй `offers/_TEMPLATE.yml` → `offers/<id>.yml` (имя файла = `id`), заполни хотя бы один язык (sk / en / uk / ru), commit. Проверка формата запустится сама; ошибки видны в Actions.

**Через форму:** студенты открывают *Issues → New issue → Suggest an offer*. Ты проверяешь и ставишь метку `approved` — файл создаётся и публикуется автоматически.

Ограничения карточки заданы для чтения «за минуту»: заголовок до 70, выгода до 60, описание до 220 символов на язык. Другие языки, кроме четырёх, валидатор не пропустит.

## Автоочистка (каждый день)

| Ситуация | Что происходит |
|---|---|
| Прошёл `valid_to` | файл переезжает в `archive/`, пост в канале помечается «⛔ Закончилось» |
| Ссылка отдаёт 404/410/ошибку **3 дня подряд** (`dead_after_failures`) | в архив |
| На странице пропал нужный текст (`check: {contains: "ISIC"}`) | считается недоступной, дальше как выше |
| Сайт блокирует ботов (403/429) | **пропускается**, оффер не страдает (если сайт за защитой — `check: {skip: true}`) |
| `verified` старше 120 дней | скрывается из каталога, но не удаляется; обнови дату, когда перепроверишь условия |
| `valid_from` в будущем | ждёт старта |
| Массовый сбой сети у самого GitHub | не наказывает офферы (защита от ложных срабатываний) |

Каждый запуск пишет отчёт в *Actions → Summary*: что скрыто, что упало, какие файлы с ошибками.

**Важное ограничение:** проверка ссылок видит «страница жива / нет нужного слова», но не понимает, что акция закончилась на живой странице. Поэтому для краткосрочных акций ставь `valid_to`, а для долгих — `check.contains` и периодически обновляй `verified`.

## Реклама (монетизация)

Рекламная карточка — это такой же файл, только в `ads/` (шаблон: `ads/_TEMPLATE.yml`): рекламодатель, даты, где показывать (`channel`, `app`), сколько постов оплачено. Выглядит как обычный оффер, но **всегда помечена** («Ad / Reklama / Реклама») и содержит название рекламодателя.

- **Канал:** после каждых `every_n_posts` обычных постов публикуется рекламный (по очереди, если рекламодателей несколько).
- **Каталог:** рекламная карточка вставляется после каждых `catalog_every` карточек.
- **Отчёт для рекламодателя:** ссылки получают UTM-метки (`utm_medium=channel` или `miniapp`), клики видны в аналитике рекламодателя; просмотры поста — в статистике канала Telegram. Своего счётчика нет: для этого нужен сервер.
- Окончание срока — автоматически (в архив). Мёртвая ссылка рекламодателя выключает карточку так же, как оффер.

Что стоит решить заранее: прайс (например, фиксированная цена за пост в канале + N дней в каталоге), и юридическую сторону (регистрация деятельности, налоги и правила рекламы в Словакии, условия Telegram). Это вопросы к бухгалтеру/юристу, не к скрипту. Условия партнёрской программы Telegram для каналов проверь в его актуальной документации.

## Что где лежит

```
config.yml           настройки, категории, лимиты, реклама
offers/              активные офферы (по файлу на оффер)
ads/                 рекламные карточки
archive/             завершённое (создаётся автоматически)
state/               служебное: состояние проверки ссылок и опубликованных постов
docs/index.html      Mini App (один файл, без сборки), docs/data/offers.json — данные для него
scripts/             build.py (проверка/очистка/данные), post.py (Telegram), intake.py (форма)
.github/workflows/   maintain (ежедневно) · post (расписание постов) · intake (форма) · validate (PR)
```

## Тонкая настройка

- **Расписание постов:** `cron` в `.github/workflows/post.yml` (время в UTC; Košice — UTC+1 зимой, UTC+2 летом). GitHub может запускать задачи с задержкой в десятки минут.
- **Сколько постов за раз:** `post.max_posts_per_run`. Очередь: сначала оффера с ближайшим сроком, потом по порядку добавления; `priority: N` поднимает вперёд.
- **Канал на каждый язык** вместо одного общего: раскомментируй `telegram.channels` в `config.yml` — тогда каждый пост уйдёт в канал на своём языке.
- **Ручной запуск:** Actions → Post to Telegram → `post | digest | menu | sync`, `dry_run=true` показывает сообщения в логе, ничего не отправляя.

## Если что-то не работает

- *Нет постов, «Нет секрета TELEGRAM_BOT_TOKEN»* — секрет не добавлен или назван иначе.
- *`chat not found` / `not enough rights`* — бот не админ канала или неверный `channel_id` (для приватного канала нужен числовой id вида `-100…`, его можно положить в секрет `TELEGRAM_CHAT_ID`).
- *Каталог пустой* — нет валидных офферов (смотри Summary последнего запуска) или не стоит `INCLUDE_EXAMPLES` при одних примерах.
- *Расписание перестало срабатывать* — GitHub отключает расписания в публичных репозиториях после 60 дней без активности; открой Actions и нажми Enable (или просто закоммить любой оффер).
- *Кнопка «Каталог» ведёт на сайт, а не в Telegram* — не заполнен `app_short_name` в `config.yml` (шаг 6).
